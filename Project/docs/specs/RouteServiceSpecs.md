# Route Service Function Specifications

The `routeService` module provides service-layer functions for managing routes, schedules, and route stops in the public transit database.

The service communicates directly with the Oracle database through the `withOracleDB` helper.

---

## Route Services

### `insertRoute()`

#### Purpose

Creates a new route in the `Route` table.

The `RouteID` is automatically generated by the service. The `RouteNumber` is supplied by the caller and must be unique according to the database constraint.

#### Function Signature

```javascript
async function insertRoute(
    routeNumber,
    routeName,
    routeDescription = null,
    colour = null
)
```

#### Parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| `routeNumber` | Number | Yes | Unique number identifying the route. |
| `routeName` | String | Yes | Name of the route. |
| `routeDescription` | String | No | Description of the route. Defaults to `null`. |
| `colour` | String | No | Colour associated with the route. Defaults to `null`. |

#### Return Value

On successful insertion:

```javascript
{
    success: true,
    routeId
}
```

If the insertion fails:

```javascript
{
    success: false
}
```

#### Notes

- `RouteID` is automatically generated.
- The generated ID follows the format:
  ```text
  R000000001
  ```
- The next ID is generated by finding the current maximum `RouteID` and incrementing its numeric portion.
- `routeNumber` must be unique.

---

### `generateRouteID()`

#### Purpose

Generates a unique `RouteID` for a new route.

#### Function Signature

```javascript
async function generateRouteID(connection)
```

#### Parameters

| Parameter | Type | Description |
|---|---|---|
| `connection` | Oracle Connection | Active Oracle database connection. |

#### Return Value

Returns a generated route ID as a string.

Example:

```text
R000000001
R000000002
R000000003
```

If no routes exist, the first ID generated is:

```text
R000000001
```

#### Notes

This is an internal helper function and is not exported from the service module.

---

### `getRouteById()`

#### Purpose

Retrieves a route using its unique `RouteID`.

#### Function Signature

```javascript
async function getRouteById(routeId)
```

#### Parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| `routeId` | String | Yes | Unique identifier of the route. |

#### Return Value

If the route exists:

```javascript
{
    routeId,
    routeNumber,
    routeName,
    routeDescription,
    colour
}
```

If no matching route exists or a database error occurs:

```javascript
null
```

# Schedule Services

### `insertSchedule()`

#### Purpose

Adds a schedule to an existing route.

A route can have multiple schedules. Each schedule specifies the operating period, applicable day type, and service frequency.

#### Function Signature

```javascript
async function insertSchedule(
    routeId,
    startTime,
    dayType,
    endTime,
    frequency
)
```

#### Parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| `routeId` | String | Yes | ID of the route associated with the schedule. |
| `startTime` | String | Yes | Start time of service in `HH:MM` format. |
| `dayType` | String | Yes | Type of day on which the schedule applies. |
| `endTime` | String | Yes | End time of service in `HH:MM` format. |
| `frequency` | Number | Yes | Frequency of service. Must be greater than 0. |

#### Valid Day Types

```text
Weekday
Weekend
Holiday
```

#### Return Value

On successful insertion:

```javascript
{
    success: true,
    routeId
}
```

If the insertion fails:

```javascript
{
    success: false
}
```

#### Notes

- A schedule belongs to a specific route through `routeId`.
- The database primary key is:
  ```text
  RouteID + StartTime + DayType
  ```
- `StartTime` and `EndTime` are stored as `VARCHAR2(5)` using `HH:MM` format.
- Database constraints validate the time format and allowed day types.

---

### `getSchedulesByRouteNumber()`

#### Purpose

Retrieves all schedules associated with a route using its route number.

The route ID is not required from the client.

#### Function Signature

```javascript
async function getSchedulesByRouteNumber(routeNumber)
```

#### Parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| `routeNumber` | Number | Yes | Route number whose schedules should be retrieved. |

#### Return Value

Returns an array of schedules:

```javascript
[
    {
        routeNumber,
        startTime,
        dayType,
        endTime,
        frequency
    }
]
```

If no schedules exist or a database error occurs:

```javascript
[]
```

#### Ordering

Results are ordered by:

1. `DayType`
2. `StartTime`

# Route Stop Services

### `insertRouteStop()`

#### Purpose

Adds a station to a route at a specified position in the route's sequence.

A route can contain multiple route stops.

#### Function Signature

```javascript
async function insertRouteStop(
    routeId,
    stopNumber,
    stationId
)
```

#### Parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| `routeId` | String | Yes | ID of the route. |
| `stopNumber` | Number | Yes | Position of the station in the route sequence. |
| `stationId` | String | Yes | ID of the station being added. |

#### Return Value

On successful insertion:

```javascript
{
    success: true,
    routeId,
    stopNumber,
    stationId
}
```

If the insertion fails:

```javascript
{
    success: false
}
```

#### Notes

- `stopNumber` must be greater than 0.
- `stopNumber` must be unique within a particular route.
- The same stop number may be used by different routes.
- The station must already exist in `TransportStation`.
- The route must already exist in `Route`.

For example, a route may contain:

```text
Route 10
    Stop 1 → Station A
    Stop 2 → Station B
    Stop 3 → Station C
```

---

### `getRouteStopsByRouteNumber()`

#### Purpose

Retrieves all stations belonging to a route using the route number.

The route ID is not included in the returned results.

The stations are returned according to their sequence on the route.

#### Function Signature

```javascript
async function getRouteStopsByRouteNumber(routeNumber)
```

#### Parameters

| Parameter | Type | Required | Description |
|---|---|---|---|
| `routeNumber` | Number | Yes | Route number whose stops should be retrieved. |

#### Return Value

Returns an array containing the stations on the route:

```javascript
[
    {
        stopNumber,
        stationId,
        stationName,
        address,
        zoneNumber,
        wheelchairAccessibility
    }
]
```

If no route stops exist or a database error occurs:

```javascript
[]
```

#### Stop Number Handling

The results are ordered using the actual `RouteStop.StopNumber`.

However, the returned `stopNumber` is regenerated based on the resulting order.

For example, if the database contains:

```text
StopNumber  Station
1           Station A
3           Station B
4           Station C
```

The service returns:

```text
StopNumber  Station
1           Station A
2           Station B
3           Station C
```

This ensures that the client always receives a continuous sequence of stops.

#### Notes

The returned result does not include `RouteID` or `RouteNumber`. The route is identified by the request itself.

# Exported Functions

The following functions are exported by `routeService.js`:

```javascript
module.exports = {
    insertRoute,
    insertSchedule,
    insertRouteStop,
    getRouteById,
    getRouteByNumber,
    getSchedulesByRouteNumber,
    getRouteStopsByRouteNumber
};
```

| Function | Purpose |
|---|---|
| `insertRoute()` | Creates a new route. |
| `insertSchedule()` | Adds a schedule to a route. |
| `insertRouteStop()` | Adds a station to a route sequence. |
| `getRouteById()` | Retrieves a route by generated route ID. |
| `getRouteByNumber()` | Retrieves a route by user-assigned route number. |
| `getSchedulesByRouteNumber()` | Retrieves all schedules for a route. |
| `getRouteStopsByRouteNumber()` | Retrieves all stations on a route in sequence order. |
